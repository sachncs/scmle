# C6 Reproducible and traceable: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

Same inputs, seed, lock file and platform give a byte-identical bundle;
across platforms, metrics within `cross_platform_tol`; every bundle traces
to its data hash, configuration, commit and environment.

## Population and data

The task kinds of `benchmarks/evidence/reproducibility.py` (binary,
multiclass, regression and a nonlinear binary task) and one task per
other data kind as each is brought into scope; each trained twice from
scratch in fresh processes with seed `SEED`, in different directories,
with `PYTHONHASHSEED` left as the caller has it. Platforms: Linux, macOS
and Windows CI runners, from the lock file.

## Split

Validation. The datasets the module generates today (`ROWS` = 600, seed
7) are development. The validation run uses data drawn from a seed never
used before, fixed in the commit that adds it.

## Statistic

Per platform and task: the bundle members that differ between the two
builds; the largest relative difference of locked-test metrics; the trace
fields missing from the manifest. Across platforms: the largest relative
metric difference over shared tasks.

## Decision rule

Policy, all-or-nothing: no differing member, no missing trace field, and
cross-platform metric gaps at most `cross_platform_tol`. No `alpha`.

`cross_platform_tol` = 1e-6 is marked "set by observation" in
`acceptance.toml`. It is re-derived from development runs on all three
platforms (the measured spread plus a margin, with the reason recorded)
and committed before the validation run. It is not changed after the
validation data are scored.

## Sample size

Not sampled: every task kind in scope, two builds each, on each of three
platforms (at least 4 kinds, 24 builds). Determinism has no error rate to
estimate.

## What counts as a failure

Any byte difference within a platform; any missing trace field; any
cross-platform metric gap beyond the tolerance; a build that crashes on
any platform; fewer than three platforms measured (not measured, which
does not pass).

## Grader

CI on clean runners, from the committed module; nobody on the builder's
laptop decides the row.

## Where the current module differs

- One platform (macOS, arm64) is recorded; the cross-platform part is
  "not measured".
- It uses the development data; its 4/4 byte-identical result was scored
  before this registration and decides nothing.
- Only tabular kinds are run.
