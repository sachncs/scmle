# C13 Every stage on steroids: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

Each speed or memory target is a ratio to a plain reference on the same
laptop: the median of `perf_repeats` runs with a bootstrap upper bound
within the target, per stage (plan section 5, C13 table). Leverage: from
the practitioner study, the bootstrap lower bound of the practitioner's
speed-up with scmle at least `speedup_min`.

## Population and data

- Stages and references: ingestion against a plain Arrow read
  (`ingest_overhead_max`, `memory_multiplier_max`); exploratory analysis
  (`first_feedback_seconds_max`, `progress_seconds_max`,
  `profile_seconds_max` at 1M rows by 100 columns, planted defects for
  `profile_recall_min` and clean tables for `profile_false_max`);
  feature engineering against raw features on benchmark tasks
  (`fe_win_share_min`, `fe_loss_max`); estimation (`estimate_minutes_max`);
  model development (`near_best_gap` by `time_to_near_best_fraction`);
  inference against the bare model (`batch_throughput_fraction_min`,
  `extras_cost_max`); serving per `docs/SERVICE_SLO.md`; iteration
  (`rerun_fraction_max`).
- Leverage: the study tasks of plan section 10.

## Split

Validation for every stage row; the study is decided in stage D on fresh
sealed tasks. Planted-defect and clean tables for profiling, and the
benchmark tasks for feature engineering, are split by table with the
seeded-hash rule; the development part re-aims the defaults in stage A
(plan section 5 allows this, with the reason recorded) and the validation
part decides. The defaults are frozen in `acceptance.toml` before the
validation part is scored.

## Statistic

Per performance target: the median ratio of `perf_repeats` = 5 runs and
its one-sided percentile-bootstrap upper bound (`bootstrap_resamples`).
Profiling: defects found over planted; false findings over clean tables.
Features: tasks where automatic features beat raw over tasks. Leverage:
per task, practitioner time alone over time with scmle at equal
anchor-relative quality; the bootstrap lower bound over tasks.

## Decision rule

- Performance: upper bound within each target (service, response or
  policy variable); every stage must pass.
- `Floor(profile_recall_min = 0.90)`, `Ceiling(profile_false_max = 0.05)`,
  `Floor(fe_win_share_min = 0.60)`, each at `alpha`; plus no feature set
  loses by more than `fe_loss_max` = 0.01 and none leaks.
- Leverage: lower bound at least `speedup_min` = 5.

## Sample size

| Variable | Rule | True rate | Alpha | Minimum | Planned |
|---|---|---|---|---|---|
| `profile_recall_min` | floor | 0.97 | 0.05 | 29 | 76 |
| `profile_false_max` | ceiling | 0.01 | 0.05 | 59 | 124 |
| `fe_win_share_min` | floor | 0.8 | 0.05 | 6 | 36 |

Performance: `perf_repeats` = 5 runs per target (policy). Leverage: the
study's group-sequential maximum, computed from the pilot (see C4); not
computable today.

## What counts as a failure

A target whose upper bound is outside it; a run that crashes or is
killed (counted at the worst ratio observed, or as a miss where no ratio
exists); a planted defect not found; a false finding on a clean table; a
feature set that leaks.

## Grader

Profiles and timings by committed scripts on the same laptop with the
load average filed; the study by the fixed script of plan section 10.

## Where the current module differs

There is no evidence module. `benchmarks/scorecard.py` reports the row as
"not measured", quoting only `speedup_min`.
