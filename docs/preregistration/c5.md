# C5 Data read and joined correctly: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

The awkward-file corpus is 100 percent correct or refused; point-in-time
features equal an independent naive implementation on at least 1,000
generated worlds and at least 5 real relational datasets; no entity,
duplicate or tied timestamp on both sides of any split.

## Population and data

- Awkward files: files a user is likely to hand over (encodings,
  delimiters, quoting, mixed types, empty and duplicate columns, large
  integers, leading zeros, date formats, truncation), in CSV, Excel,
  Parquet, Feather and through the streaming reader, each with an expected
  table or an expected refusal written by hand.
- Worlds: random parent, child and leaf schemas of
  `benchmarks.qualification.ingest_checks.random_schema`; the product's
  synthesis against `benchmarks.qualification.ingest_naive`.
- Real relational datasets: at least `REAL_DATASETS` = 5 public
  multi-table sets (RelBench or similar), compared with the naive
  reference on the same cut-off times.
- Split hygiene: every split the product makes on those datasets.

## Split

Validation. The 34 files of `reading.corpus` are development (the builder
wrote them and fixes the reader against them). The validation corpus is
a second set of files and expectations written by someone else and sealed
before it is read. Worlds use the seed stream
`evidence.reading.schema.validation`; today's
`evidence.reading.schema` is development. The real datasets are chosen
and committed before any is run.

## Statistic

Counts: files `correct`, `refused` (with over-refusal of a readable file
reported) and `wrong`; worlds and real datasets equal within tolerance;
splits with a shared entity, duplicate or tied timestamp.

## Decision rule

Policy, all-or-nothing: zero `wrong` files, every world and every real
dataset equal within `reference_rel_tol` = 1e-8 (relative and absolute),
zero splits with leakage across them. No `alpha`.

## Sample size

Not sampled for a rate: at least 1,000 worlds (the plan's count), at least
5 real datasets, and every file in the validation corpus (at least as many
as the development corpus, 34). The rule allows no error, so a larger
sample only makes it stricter.

## What counts as a failure

A table returned that differs from the expected one, or returned where a
refusal was expected; a world or dataset that differs; a crash other than
`DataError` on a file; a split that shares an entity, duplicate or tied
timestamp. A refusal of a readable file is not a failure of this row but
is reported (it counts towards C14).

## Grader

Expected tables are written by someone other than the reader's author;
the naive reference is kept independent of the product's code; the
script runs in CI.

## Where the current module differs

- `reading.py` reads CSV only through `read_table`: Excel, Parquet,
  Feather, the streaming reader and database connectors are not read.
- Real relational datasets and split hygiene are not measured, so the
  best verdict it can give is "not measured".
- The builder wrote the corpus and its expectations.
- Its result (9 of 34 files silently wrong; 1000/1000 worlds equal) was
  scored before this registration and decides nothing.
