# C8 Controls cannot be bypassed: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

Zero successful bypasses of the written goals in a time-boxed red-team
exercise; a regression test per attempt.

## Population and data

The release candidate of stage D. The written goals, from the plan:
self-approve, reuse confirmation data, clear a halt, deploy an unapproved
or swapped bundle, pass the audit without evidence, reset alarms. The
goals are committed before the exercise; the red team may add goals, which
are then scored the same way.

## Split

None applies: the exercise is run once in stage D on the release
candidate. Attempts made before it (by the builder, in tests) are
development. A fix after a successful bypass needs a new time-boxed
exercise on the fixed candidate.

## Statistic

Count of successful bypasses, per goal; count of attempts, each with its
regression test.

## Decision rule

Policy: zero successful bypasses, and one committed regression test per
attempt (successful or not). No `alpha`; `acceptance.toml` has no
variable for this row (the scorecard quotes `alpha` only as a
placeholder).

## Sample size

Not a rate: every written goal attempted by every red-team member within
the time box. The time box and the number of red-team members are not
yet in `acceptance.toml`; the owner sets them, with a reason, before the
exercise, and they are recorded there as policy variables.

## What counts as a failure

Any goal reached without the control stopping it or recording an
override the governance allows; an attempt without a regression test.

## Grader

A red team that did not build the product, arranged by the owner. The
builder fixes; it does not judge whether an attempt succeeded.

## Where the current module differs

There is no evidence module. `benchmarks/scorecard.py` reports the row as
"not measured".
