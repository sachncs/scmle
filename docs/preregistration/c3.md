# C3 Statistics correct and uncertainty honest: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

Every reported statistic within `reference_rel_tol` of a reference
implementation, and gate-deciding statistics also match a second
implementation; 95 percent metric intervals cover fresh-data metrics with
lower bound at least `interval_coverage_min`; on at least `null_tasks_min`
null tasks, skill claimed with upper bound at most `null_skill_max`; every
interval and test at nominal by simulation-based calibration; confirmation
data, test set and exploration budget spent once per analysis.

## Population and data

Simulated tasks from known worlds, so the truth is known.

- Coverage: the families of `benchmarks/evidence/coverage.py`
  (`binary_rows`, `regression_rows`, `binary_groups`) plus multiclass log
  loss and temporal block resampling. One trial fits the product's
  pipeline on `TRAIN_ROWS`, asks `Uncertainty.compute` for the interval on
  `TEST_ROWS`, and scores the same model on `FRESH_ROWS` fresh rows.
- Null skill: tasks whose target is independent of the features, run
  end to end; a hit is a run that claims skill: its CV or test interval
  lies wholly better than the dummy baseline, or its fit verdict is
  healthy (`evaluation.health.verdict == healthy`). `overfit` and
  `unstable` are not claims, because the product then says the gain does
  not survive validation or is too noisy to rank. A crash counts as a
  claim, a refusal does not, and an unknown metric direction is refused.
- Reference agreement: every statistic the product reports, on fixed
  inputs, against a reference library (and a second implementation for
  gate-deciding ones).

## Split

Validation, on seed streams never drawn: coverage trials seed
`default_rng([trial, family index, 1])` (the trailing 1 marks validation;
today's `[trial, family index]` stream is development). Null tasks use the
stream `coverage.null.validation`.

## Statistic

Per coverage family: hits over trials. Null: runs claiming skill over null
runs. Reference: largest relative error per statistic.

## Decision rule

- Coverage: per family, `Floor(interval_coverage_min = 0.93)` lower bound
  at `alpha`; the worst family decides, the pooled count decides nothing.
- Null skill: `Ceiling(null_skill_max = 0.05)` upper bound at `alpha`.
- Reference: every statistic within `reference_rel_tol` = 1e-8 (policy).
- Calibration and single-spend clauses: policy, every case must hold.

## Sample size

| Variable | Rule | True rate | Alpha | Minimum | Planned |
|---|---|---|---|---|---|
| `interval_coverage_min` | floor | 0.95 | 0.05 | 42 | 882 |
| `null_skill_max` | ceiling | 0.01 | 0.05 | 59 | 124 |
| `null_skill_max` | ceiling | 0.02 | 0.05 | 59 | 234 |

Coverage: 882 trials per family, at a true coverage equal to the nominal
0.95. Null: `null_tasks_min` = 200 tasks (policy) is registered; its exact
power is 0.95 at a true rate of 0.01 and 0.63 at 0.02, so a product
claiming false skill twice in a hundred tasks would pass less than two
times in three. The `null_tasks_min` derivation in `acceptance.toml`
sizes for detecting a rate of 0.10, which is a different question.
`benchmarks/evidence/nulls.py` plans 577 tasks instead: the smallest count
whose exact chance of passing reaches power 0.80 at an assumed rate of
`null_skill_max / (1 + size_margin)` = 0.0296.

## What counts as a failure

A family below the floor; a trial that errors (counted as not covered); a
null run claiming skill; a statistic beyond the tolerance; a resume or
amendment that spends confirmation data or the test set twice.

## Grader

The coverage and null scripts, committed before the validation stream is
drawn; reference values come from third-party libraries, not the builder.

## Where the current module differs

- `coverage.py` measures only coverage, on three families; multiclass log
  loss, temporal resampling, real data and other model families are not
  measured.
- Reference agreement and the second implementation are measured by
  `benchmarks/evidence/statistics.py` (`summary()` for reported
  statistics, `summary(scope="deciding")` for gate-deciding ones).
- Null skill is measured by `benchmarks/evidence/nulls.py` on 577 planned
  tasks (315 permutations of the 35 pinned C4 tables and 262 simulated
  tables), not the registered 200, with the hit rule above.
- Calibration is measured by `benchmarks/evidence/calibration.py`; its
  verdict stays `partial` while any product interval or test is not
  calibrated by a scenario.
- Single spend is not measured by any module.
- It uses the development seed stream; its 816/882 worst-family result
  was scored before this registration and decides nothing.
