# C10 Can keep changing safely: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

Adding a model family, task type, data kind, metric or reader each touches
at most `change_cost_files_max` files outside its own new package, done as
a scripted exercise; an import-layer contract over every package with zero
exceptions; size budgets (`module_lines_max`, `class_lines_max`,
`function_lines_max`); mutation score at least `mutation_score_min` per
gated module with crashes classified; no test that cannot fail;
pull-request checks within `ci_minutes_max`.

## Population and data

The package `scmle/` at the commit scored; its gated modules (those that
hold a registered gate in `gates.toml`); the five change exercises
(one each: model family, task type, data kind, metric, reader), written
as tasks before stage B ends.

## Split

Validation. The exercises are drawn from a list of candidate extensions
written before stage B; the builder does not see which are chosen.
Mutants have no split: every generated mutant of a gated module is scored.

## Statistic

Files touched outside the new package per exercise; import-contract
violations; modules, classes and functions over budget (as
`scripts/structure.py` counts them); per gated module, killed mutants
over scored mutants (killed, survived, timeout) after equivalent mutants
are removed; tests that pass on every mutant of their target; CI minutes.

## Decision rule

- Mutation, per gated module: `Floor(mutation_score_min = 0.85)` lower
  bound at `alpha`, with crashes classified (a crash that is a correct
  refusal counts as killed only when classified so).
- Everything else policy, all-or-nothing: each exercise at most 3 files,
  zero contract exceptions, zero items over 800/300/80 lines, zero tests
  that cannot fail, CI at most 15 minutes.

## Sample size

Assumed true mutation score 0.95:

| Variable | Rule | True rate | Alpha | Minimum | Planned |
|---|---|---|---|---|---|
| `mutation_score_min` | floor | 0.95 | 0.05 | 19 | 59 |
| `mutation_score_min` | floor | 0.90 | 0.05 | 19 | 281 |

A gated module with fewer than 19 scored mutants cannot pass; it is
merged with the module it serves or given more mutation operators. The
planned 59 holds at a true score of 0.95; a module whose true score is
0.90 needs 281.

## What counts as a failure

An exercise over 3 files; any contract exception; any item over budget; a
gated module below the floor or under the minimum; an unclassified crash;
a test that cannot fail; CI over 15 minutes.

## Grader

The exercises are done by someone new to the code; import-linter,
`scripts/structure.py` and mutmut run in CI.

## Where the current module differs

- `scripts/structure.py` measures size budgets and naming only, and
  ratchets against `scripts/structure.json` rather than deciding against
  zero.
- `scripts/check_mutation_score.sh` uses a single integer-percent
  threshold (default 70) over the whole mutation scope, not a
  Clopper-Pearson floor of 0.85 per gated module.
- The change exercises, the import contract, the cannot-fail test check
  and CI time have no evidence feeding the scorecard.
- `benchmarks/evidence/mutation.py`, which the scorecard reads, scores a
  stratified sample of modules, not each gated module, and pools their
  mutants under one floor. It classifies no crash, so every crash counts
  as a mutant not killed, and it removes no equivalent mutant.
