# C7 Operates without loss or stall: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

Service objectives met under load plus a 24-hour soak with flat memory; a
hung request cannot wedge a replica; zero reset connections on SIGTERM;
kill -9 at every stage boundary, journal append and lease operation
resumes to an identical result with no lost or duplicated record; lease
and journal protocols model-checked; at least `budget_compliance_min` of
runs within their declared time and memory budget.

## Population and data

- Budget compliance: end-to-end runs of `Project.run` with a declared time
  and memory budget, over a design of budgets (20 s, 60 s, 300 s), task
  kinds and data sizes fixed in the commit that adds it; one run per
  (design cell, data seed).
- Kill and resume: one uninterrupted reference run per task, then a run
  killed with SIGKILL (whole process group) at each stage boundary, each
  journal append and each lease operation, resumed in a new process.
- Service: the load profile of `docs/SERVICE_SLO.md`, a 24-hour soak, a
  hung-request test and a SIGTERM test.
- Protocols: TLA+ models of the lease and journal.

## Split

Validation, on data seeds never drawn: the seeds 0 to 399 used by
`benchmarks/evidence/budget.py` are development; validation starts at a
seed offset fixed in the commit that adds it.

## Statistic

Compliance: runs that completed within budget plus the product's grace
(`max(limits.GRACE_SHARE * budget, limits.MIN_CEILING_SECONDS)`) and
within their memory budget, over runs. Resume: resumed results differing
from the reference, field by field. Service: the SLO measures.

## Decision rule

`Floor(budget_compliance_min = 0.99)` lower bound at `alpha` = 0.05 for
compliance. Every other clause is policy, all-or-nothing: zero differing
resumes, zero lost or duplicated records, zero reset connections, no
wedged replica, flat soak memory, model checks with no counterexample.

## Sample size

Assumed true compliance 0.999 (one overrun in a thousand runs):

| Variable | Rule | True rate | Alpha | Minimum | Planned |
|---|---|---|---|---|---|
| `budget_compliance_min` | floor | 0.999 | 0.05 | 299 | 473 |
| `budget_compliance_min` | floor | 0.997 | 0.05 | 299 | 913 |

473 runs are registered. Kill and resume: one kill per kill point, every
kill point (not sampled).

## What counts as a failure

A run over its time or memory budget; a run killed at `TIMEOUT_FACTOR`
times its allowance (counted as over); a crash (counted as not within
budget); any resumed result that differs; any SLO miss under the stated
load.

## Grader

The committed module in CI; load and soak by a script fixed before the
run; a history checker for the journal. The builder does not grade by
reading logs.

## Where the current module differs

- `budget.py` decides compliance on real tables, not on the registered
  design: the OpenML tasks cached for C4 and the tables of C14's `EXTRA`
  list (`budget.tables()`), each given a time budget scaled from its size
  by `allot` (30 s up to 10,000 cells, doubled for every tenfold more)
  instead of the 20 s, 60 s and 300 s design. It measures the time budget
  only, on a shared laptop; memory budgets are not measured.
- The real tables are not split into development and validation: pass `k`
  seeds a table with `seed_for(id, 0, k)`, so pass 0 of a C4 table reuses
  C4's seed, and every real run that is not refused counts.
- One pass is one run per table, so the 299 runs the floor needs (473
  planned) take several full passes with distinct seeds, more than the
  one-hour window holds.
- The `RUNS_MAX` = 400 seeded practice runs (`reliability.fast_project`,
  20 s, data seeds 0 to 399) are reported beside the row but never
  decide; they were measured under the old rule of budget plus grace.
- Kill points are after 1, 2 and 3 trial checkpoints of the training
  stage only; stage boundaries, journal and lease operations are not.
- Service load, hung requests and SIGTERM are measured by
  `benchmarks/evidence/service.py`; the 24-hour soak has no stored run.
- Model checking is `benchmarks/evidence/protocols.py`: Python transition
  systems checked by explicit-state breadth-first search and replayed
  against the real code, not TLA+. Duplicate custody verdicts are outside
  the model by design: a resume decides every gate again.
- Its 400/400 and 3/3 results were scored before this registration on
  development seeds and decide nothing.
