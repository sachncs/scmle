# C1 No silent wrong outcome: pre-registration

Registered 2026-11-17. Shared rules: [README.md](README.md).

## Criterion

Every gate is in the registry (`gates.toml`, checked by
`benchmarks/registry.py`) with a pass, a block and an override path; an
unregistered gate fails CI. Every injected failure ends in a block or a
recorded override. Every certificate is read by the code it justifies.

## Population and data

The unit is one (gate, failure mode) pair, plus one unit per gate with a
documented override (the same failure under that override). The registered
failure modes, from the plan, are: missing file, stale certificate,
exception, NaN, empty input, skipped stage, and the condition the gate
itself guards. A mode that cannot reach a gate is listed with the reason
and excluded only when the validator agrees. Inputs are simulated tables
(the faults are planted), as in `benchmarks/evidence/faults.py`.

## Split

Validation. The fault suite has no sampled data, so the split is of the
injections: the injections in `faults.INJECTIONS` today are development
(the builder wrote them while fixing gates). The validation suite is a
second set of injections, one per (gate, mode), written by someone who
did not write the gate, committed with its hash before it is run.

## Statistic

Share of units whose outcome is `blocked` or `override` (the module's
`SATISFIED`), over all registered units. A unit `not injected`, `failed`
or `silent` is in the denominator.

## Decision rule

`gate_fault_block_min` = 1.0 (kind policy, no statistical rule): passes
only when every unit is satisfied and every registered gate was attempted.
`alpha` does not apply. The certificate clause passes when a static check
finds, for every certificate kind, a reader in the code path it justifies;
there is no such check yet.

## Sample size

Not sampled: the whole registry at the commit scored, 43 gates and 9
overrides today, times the failure modes that reach each gate. The
registry is the population, so no power calculation applies; adding a gate
adds its units.

## What counts as a failure

Any `silent` unit (the call continued and nothing records the fault); any
`failed` unit (another exception ended it, which is not a block); any unit
not injected without the validator's agreement; any gate in the code that
is not in the registry; any certificate with no reader.

## Grader

The validation injections are written by someone other than the gate's
author and run by CI from the committed suite. The builder may fix gates
but does not edit the validation injections.

## Where the current module differs

- `faults.py` injects one condition per gate (the one it guards), not the
  plan's failure-mode taxonomy; NaN, empty, exception, missing file, stale
  certificate and skipped stage are not each injected at each gate.
- The builder wrote both the gates and the injections; the plan asks for a
  suite written by someone else.
- "Every certificate read by the code it justifies" is not measured.
- Its 52/52 result was scored before this registration and on the
  development injections, so it decides nothing.
