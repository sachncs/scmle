No slice is qualified. This page says, for each task family and modality, what exists in the repository, what does not, and what a slice needs before it may be called production-supported. It is the audit F15 item 15 asks for, and it is a status table, not a roadmap.

The rule

A slice is qualified only when all three hold:

  1. its robustness, drift, explanation and monitoring benchmark was defined before it was built (the files in benchmarks/breadth/ do that) and was then run, with a public or domain benchmark and an independent replication;
  2. it completes ingestion, evaluation, packaging, deployment, monitoring and recovery;
  3. its deployment requirement was declared by a named owner.

Partial means some code exists and is tested but not all of that. Not supported means nothing in the repository does the job. An unsupported algorithm is never added to the production registry; the guard test tests/unit/test_breadth.py::test_unsupported_algorithms_are_not_in_the_model_registry fails if one is.

Built is the word in the definition file. Qualified is no for every slice. All fourteen benchmark definitions are not_run, and every threshold in them is unset until the owner fixes it.

The "experimental" modality lifecycles are baselines that prove the lifecycle holds together on the author's machine. Their own reports say so and carry the limits quoted above; the declaration they produce has the status experimental, never supported, and only the contract module can name a supported modality (a guard test checks this).

Data kinds on the shared stages

Separately from those lifecycles, every data kind is registered in scmle.pipeline.kinds.KINDS and runs through the same stages as a table: ingestion reads through kind.read, profiling surveys through kind.survey, the split takes kind.constrain, time-budget admission prices kind.cost, training featurises through kind.featurise and packaging decodes through kind.decode. scmle run DATA --target Y --modality KIND picks the kind; the kinds are tabular, document, graph, image, video, audio, raster and geospatial.

One shared splitter (rows.Cohorts) keeps copies, near-copies, declared groups and spatial blocks on one side of every split and fold. With a time-ordered protocol it purges development rows that share a cohort with a test row; an exchangeable protocol becomes the group split, with a note; a declared group with missing values is refused; when no cohort holds two rows the declared protocol applies.

Each kind declares its own capability records (Kind.declare()), and roster.enrol enrols them. Every kind except tabular is declared experimental, not supported: supported means the whole lifecycle is proven, and deployment, monitoring and recovery are not proven for these kinds. A run of any of them needs the opt-in models.experimental_models in the --config file, naming the model families the task accepts; without it the run is refused with an UnsupportedError. geospatial (vector) has two more reasons: a served model takes the geometry columns, not raw GeoJSON, and the held-out test interval resamples rows, not spatial blocks, so it can be too narrow.

What every non-tabular kind does not do: a served model takes described rows (descriptor or feature rows), not raw files; the descriptors are hand-built, not a learned or pretrained representation. Admission uses each kind's own cost, so a media kind needs a larger time budget than a table of the same row count. Optional libraries are needed for some inputs: Pillow (images, the multimodal extra), ffmpeg and ffprobe on the PATH (video), soundfile (FLAC audio), rasterio (GeoTIFF), pypdf (PDF, the documents extra) and geopandas (vector formats other than GeoJSON). The Built column keeps the definition files' word, which predates these kinds.

Streaming and delivery semantics

Exactly-once streaming is not claimed. SCMLE has no event-streaming pipeline. The word "streaming" in the code means reading a table that is larger than memory in chunks. The one delivery path that exists, the telemetry spool, delivers at least once, so a destination can see duplicates. A streaming slice would first need the owner to state the semantics the consumer needs, and its evidence would be a kill at every stage of the whole pipeline with the effects compared with a batch computation; per-stage results do not add up to an end-to-end one.

Benchmark definitions

Each file in benchmarks/breadth/ defines four benchmarks (robustness, drift, explanation, monitoring) with the damage or signal, the ground truth, the metric and the pass rule, plus the deployment requirement to be declared, the external referent and the lifecycle stages required. Parameters are null until the owner fixes them before building, not by fitting them to a result. tests/unit/test_breadth.py checks that each file is well formed, that nothing in it is run, fixed or declared, and that the cited evidence exists.

Registry guard

tests/unit/test_breadth.py fails if the production registry gains a supported capability outside tabular library inference, a supported pretrained, multimodal or JEPA family, a supported streaming path, a clustering, association, dimensionality-reduction, forecasting-specific or deep modality model name in the model registry, a clustering or association task type, or a supported modality declaration outside the contract module. An adapter a caller registers is extension-only.
