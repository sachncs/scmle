No slice is qualified. This page says, for each task family and modality, what exists in the repository, what does not, and what a slice needs before it may be called production-supported. It is the audit F15 item 15 asks for, and it is a status table, not a roadmap.

The rule

A slice is qualified only when all three hold:

  1. its robustness, drift, explanation and monitoring benchmark was defined before it was built (the files in benchmarks/breadth/ do that) and was then run, with a public or domain benchmark and an independent replication;
  2. it completes ingestion, evaluation, packaging, deployment, monitoring and recovery;
  3. its deployment requirement was declared by a named owner.

Partial means some code exists and is tested but not all of that. Not supported means nothing in the repository does the job. An unsupported algorithm is never added to the production registry; the guard tests in tests/unit/test_breadth.py fail if one is.

Built is the word in the definition file. Qualified is no for every slice. All fourteen benchmark definitions are not_run, and every threshold in them is unset until the owner fixes it.

The "experimental" modality lifecycles are baselines that prove the lifecycle holds together on the author's machine. Their own reports say so and carry the limits quoted above; the declaration they produce has the status experimental, never supported, and only the contract module can name a supported modality (a guard test checks this).

Streaming and delivery semantics

Exactly-once streaming is not claimed. SCMLE has no event-streaming pipeline. The word "streaming" in the code means reading a table that is larger than memory in chunks. The one delivery path that exists, the telemetry spool, delivers at least once, so a destination can see duplicates. Before any streaming slice, the owner must state the semantics the consumer needs, and the evidence must be a kill at every stage of the whole pipeline with the effects compared with a batch computation; per-stage guarantees do not add up to an end-to-end one.

Benchmark definitions

Each file in benchmarks/breadth/ defines four benchmarks (robustness, drift, explanation, monitoring) with the damage or signal, the ground truth, the metric and the pass rule, plus the deployment requirement to be declared, the external referent and the lifecycle stages required. Parameters are null: the owner fixes them before building, and never fits them to a result. tests/unit/test_breadth.py checks that each file is well formed, that nothing in it is run, fixed or declared, and that the cited evidence exists.

Registry guard

tests/unit/test_breadth.py fails if the production registry gains a supported capability outside tabular library inference, a supported pretrained, multimodal or JEPA family, a supported streaming path, a clustering, association, dimensionality-reduction, forecasting-specific or deep modality model name in the model registry, a clustering or association task type, or a supported modality declaration outside the contract module. An adapter a caller registers is extension-only.
