# Validation referents: what shows the result is right

Canon: [`00-canon.md`](00-canon.md). Feature: F7 in
[`../product/features.md`](../product/features.md). The author and the user are
not evidence. Each claim below is tied to something that can disagree with
us.

## Rule

A claim is not made until its referent has been run and its pass criterion met
on inputs fixed before the run (hashes, seeds, thresholds). A failed referent
is published with the result, as `benchmarks/sota/PROTOCOL.md` already requires
of losses (section 6, rule 6).

## 1. Labelled corpora of known defects

All items are **candidate: existence, licence and hash to be verified**. None
is claimed to exist in the form described until checked.

| Defect | Candidate source (name only) |
|---|---|
| Label errors | Datasets with published, human-adjudicated label-error audits (for example the "Pervasive Label Errors in Test Sets" study corpora) |
| Leakage via recording | Titanic `boat` / `body` (already referenced in the README); documented leaky Kaggle datasets |
| Duplicates and train/test overlap | CIFAR-style duplicate audits; datasets with published near-duplicate lists |
| Sentinels and impossible values | UCI datasets with documented `-1`/`999` missing codes |
| Missingness mechanisms | Clinical datasets with documented MNAR; the repo's own fixtures |
| Shift | Public datasets with documented temporal or site shift |
| Tabular task pool | TabArena-v0.1 tasks already pinned in `benchmarks/sota/tasks_tabarena_v0pt1.csv` (verified present; rows/columns per the protocol, section 2) |

Procedure: record name, licence, retrieval date and SHA-256 per file in a
corpus manifest; reject any file whose hash differs. Where adjudication is
missing, the corpus is used only for injection, not as ground truth.

## 2. Reference implementations

| Our quantity | Compared with | Compared on | Tolerance (proposed) |
|---|---|---|---|
| chi-square, Fisher, KS, rank tests | scipy | frozen tables | relative 1e-8 |
| ADF, KPSS, Little's MCAR (if built) | statsmodels | frozen series | relative 1e-6; MCAR may differ by method, stated |
| LORD++, SAFFRON, ADDIS, e-LOND decisions | R `onlineFDR` | frozen p-value streams | decisions identical |
| Knockoff selection | R `knockoff` | frozen X, y, seeds | same selected set; W statistics in distribution |
| Label-issue ranks | `cleanlab` | frozen probabilities | top-k overlap >= 0.9 |
| Bootstrap intervals | existing SOTA statistics | frozen inputs | interval ends within Monte Carlo error |

Fixtures are generated by a committed script that records tool versions.
Differential agreement shows we implemented the reference, not that the
reference is right; closed-form null checks (KS uniformity at level 0.001)
cover that gap.

## 3. Prospective and forward-in-time outcomes

- The forward holdout `F` is judged once: confirmed claims must keep sign and
  stay within the charter's stated size band.
- Production: for any deployed run, log qualification verdicts, then compare
  later realized model performance with the validation estimate. A `pass`
  that is followed by a degraded out-of-time score is a recorded miss.
- Backtest (F7): `block` vs `pass` against a pre-defined out-of-time gap, with
  the circularity and selection rules of F7 in `../product/features.md`.

## 4. Independent replication

Reuse the SOTA protocol: tagged protocol before results, hold-out opened once,
raw results archived with SHA-256, statistics script unchanged
(`benchmarks/sota/PROTOCOL.md` sections 1-6). Proposed addition: an outside
party reruns the qualification benchmark from a clean clone and files their
numbers unedited. The nightly workflow already rehearses a clean-clone run
(`.github/workflows/full-suite.yml`, clean-clone job); an external run is the
stronger form of it.

## 5. Domain-owner sign-off record

A signed, hashed JSON appended to the decision log; no sign-off, no
`attested` tier.

```json
{
  "charter_hash": "...", "field": "...", "statement": "origin / as-of / meaning",
  "evidence": "log table, DDL, ticket id, document id",
  "role": "data owner", "name_or_id": "...", "date": "YYYY-MM-DD",
  "scope": "this dataset version (hash)", "expires": "YYYY-MM-DD",
  "signature": "..."
}
```

Sign-off is accepted only if it names evidence a third party could check.

## 6. External statistician review checklist

- Is the estimand stated and does each claim answer it?
- Is the guarantee attributed to the confirmation set only (P2)?
- Are online-FDR assumptions (independence or dependence) stated and matched
  by the rule chosen?
- Do permutation controls respect group and time structure?
- Is every threshold either derived or pre-registered, with its measured
  operating characteristic?
- Are intervals reported for every recall/size claim, with B justified?
- Could a successful analyst attack exist that the red-team did not try?
- Are multiplicity families defined before data were seen?

## 7. Claim -> referent -> pass criterion

| Claim | Referent | Pass criterion |
|---|---|---|
| Confirmed claims have FDR <= alpha | Semi-synthetic simulator on real X | Upper limit of mean FDP <= alpha + 0.01 |
| p-values are valid | Closed-form null KS | KS p >= 0.001 per test; P(p<=0.05) in binomial band |
| Statistics are implemented right | scipy / statsmodels / R oracles | Tolerances in section 2 |
| Detector D finds defect type T | Injection + labelled corpus | Lower Wilson bound of recall >= pre-registered floor |
| Detector D does not over-alarm | Clean copies | Upper bound of false-alarm rate <= ceiling |
| Tests catch broken statistics | Mutation testing | No surviving comparison/sign mutant in `ledger/` |
| Sealed sets stay sealed | Access-attempt tests + open log | All attempts refused or logged; hash chain verifies |
| A `pass` predicts later health | Backtest on out-of-time gap | Pre-registered contrast, interval excludes zero, or "unsupported" |
| System resists false findings | Red team | Zero successes; bound reported |
| Results reproduce | Outside clean-clone run | Same hashes and decisions |
| Provenance is right | Signed domain-owner record | Evidence named and checkable |

## Limits

These referents bound the error; they do not eliminate it. Corpora are finite,
planted errors are easier than real ones, and sign-off is only as good as the
signer's evidence. The report must say so.
