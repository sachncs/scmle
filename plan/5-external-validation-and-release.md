# Stage 5: External validation and release

Names follow [`00-canon.md`](00-canon.md). Item classes and reasons:
[`COMPLETION_AUDIT.md`](COMPLETION_AUDIT.md), "Stage 5". Referents:
[`validation-referents.md`](validation-referents.md). Feature F7 in
[`../product/features.md`](../product/features.md). Depends on stage 1; the
sign-offs rest on the limits stage 3 closes. Everything here needs people,
data or decisions from outside the author, so the lanes start early and the
release is last.

## Goal

Show, with evidence that is neither the author's nor the user's (P1), that the
instrument is right, then release it through the existing evidence chain.

## Starting point (2026-11-08)

* Not published: `https://pypi.org/pypi/scmle/json` returns 404. `README.md`
  and `website/src/pages/index.astro` install with
  `pip install "scmle @ git+https://github.com/sachncs/scmle"`.
  `pyproject.toml` has `version = "0.1.0b1"`; `CHANGELOG.md` has a `0.1.0b1`
  section and a large `Unreleased` section; the only tag is
  `sota-protocol-v1`.
* The release pipeline exists (`.github/workflows/release.yml`,
  `docs/RELEASING.md`) and has never run.
* `SECURITY.md` and `CITATION.cff` exist; `tests/unit/test_citation_file.py`
  checks the required keys and the version, and `cffconvert` itself has not
  been run.
* Two controls need people: an operational rehearsal reviewed by someone other
  than the author (`docs/OPERATIONS_REHEARSAL.md`), and a signed independent
  review checked by `scripts/verify_release_review.py`.
* `benchmarks/sota/PROTOCOL.md` is a tagged pre-registration
  (`sota-protocol-v1`); the same discipline is reused here.

## Entry criteria

1. Stage 1 done: one fully green `ci.yml` run on the head, every job read; the
   release is cut from a clean tree.
2. The certification items R1-A5 and R1-A6 closed or accepted: certificates for
   the gating detectors are on file and the open limits are written in docs. A
   detector that is `descriptive` does not block this stage; a claim that it
   gates does.
3. `benchmarks/qualification/PROTOCOL.md` committed and tagged
   `qualification-protocol-v1` before any backtest or replication result
   exists (item 5.1).

## Work packages

### 5.A Qualification evidence (F7)

| Items | Scope | Closing criterion |
|---|---|---|
| 5.1 (D) | Protocol: claim, corpora list, thresholds, stop rules, amendment rule (no change to thresholds or corpus assignment after results). Mirrors `benchmarks/sota/PROTOCOL.md` | tagged before results |
| 5.2 | Fill every `candidate` entry in `benchmarks/qualification/corpora.json` (source URL, licence, SHA-256, size, adjudication source) or remove it; hold-out assigned by hash | at least 15 datasets with at least 5 per defect family, or the claim is narrowed to the families covered; hashes verified by the fetcher |
| 5.3 | Backtest (`benchmarks/qualification/backtest.py`): do datasets the instrument says `block` show a larger out-of-time gap than those it says `pass`? Gap definition, reference model and metric are fixed before any verdict; the verdict never reads the later period; corpus membership fixed by a written inclusion rule and hash list; compare within strata (size tercile by task type) with an adjusted effect; one pre-registered primary contrast, per-check contrasts secondary and BH-adjusted | one contrast run once on hold-out, with interval; if fewer than 15 datasets have a time axis the outcome is "unsupported" and go/no-go row 4 stays open |
| 5.4 | Red team: an analyst who did not write F1 to F6 and has not read the detector code gets 3 datasets and a rules sheet (attack budget in hours and full runs per attempt fixed in advance) and tries to push a planted-null feature to `confirmed` or get a planted leak admitted using legal inputs only. Success is a trial; report successes out of attempts with an exact binomial interval. Known attack surface on the sheet: re-running with different seeds or charters, the caller-held copy of the data, the non-charter path which has no custody | `benchmarks/qualification/redteam/report.json` lists attempts, successes and the upper bound; every success maps to a regression test and a ledger rule |
| 5.5 | Independent replication: a third party reruns the qualification campaign from a tag on a fresh machine using only the committed protocol | statistics within the protocol tolerance, or the gap explained in a dated amendment |
| 5.6 | TabArena campaign (`benchmarks/sota/campaign.py` and the pinned tasks): the calibration step, the development run, then the hold-out opened once. A model-accuracy claim about the modelling stages, not about the instrument; about 9 machine-days | result files with SHA-256 checksums; claim reported met or not met; losses published |
| 5.7 | R oracle fixtures generated by a reviewer with R: `onlineFDR` (LORD++, SAFFRON, LOND, ADDIS), `knockoff`, `dagitty`, frozen in `tests/fixtures/oracles/` with the generator script, versions and a content hash. `onlineFDR` 2.20.0 has no e-LOND function, so e-LOND keeps only its closed-form and simulation checks | decisions exact, levels to 1e-9 |
| 5.8 (A) | Repo-wide mutation floor: run mutmut over the full configured scope and the modules missing from it; commit per-module survivors in `benchmarks/qualification/mutation_survivors.json` with each survivor killed by a new test or justified in one line; 100 percent of comparison, constant or sign mutants in `ledger/` and p-value code killed or justified | `./scripts/check_mutation_score.sh 80` exits 0 with the custody, charter and vault modules in scope. The floor changes only by a dated change here |
| 5.9 | Domain-owner pilot: one real dataset run by a team that owns it; the owner reviews the provenance table, admissibility and mechanisms | a signed record that each mechanism is plausible or flagged; flags become issues |

## Exit gate

```bash
uv run python -m benchmarks.qualification --check all
uv run python -m benchmarks.qualification.backtest --protocol qualification-protocol-v1
./scripts/check_mutation_score.sh 80
./scripts/release_preflight.sh
python scripts/verify_release_review.py review.json --source-commit <sha>
python scripts/verify_external_release.py   # after publish; arguments per scripts/README.md
pip install "scmle==<version>"              # in a clean environment
```

## Go / no-go checklist (all must hold; the signer is never the author)

| # | Criterion | Threshold | Signer |
|---|---|---|---|
| 1 | Null size, every gating detector | upper Wilson bound inside the stated ceiling over at least 1000 replicates | Independent statistician |
| 2 | Recall on planted defects | Wilson 95% lower bound at least the file's floor per type (0.80; leakage 0.90); uncertified types listed as descriptive | Independent statistician |
| 3 | Real-corpus recall | at least 0.70 on hold-out corpora, with interval; or "not measured" stated | Independent reviewer |
| 4 | Predictive validity | gap(block) > gap(pass), one-sided p < 0.05, or "unsupported" stated | Independent statistician |
| 5 | Final-claim FDR | empirical FDR upper limit <= alpha_confirm + 0.01 on semi-synthetic data | Independent statistician |
| 6 | Access control | 0 successful reads of `C` or `F` in red team and tests; open custody gaps listed in `docs/SECURITY.md` | Red-team analyst |
| 7 | Red team | 0 open high-severity attacks | Red-team analyst |
| 8 | Replication | third-party statistics within tolerance | Replicating party |
| 9 | Domain pilot | owner sign-off recorded | Domain owner |
| 10 | Mutation score | at least 80 on the configured scope including custody, charter and vault | CI; non-author approves config |
| 11 | Release controls | rehearsal reviewed; `verify_release_review.py` exits 0 | Independent reviewer |
| 12 | Docs, API, citation | items 5.14 and the API fixture done | Maintainer other than author |
| 13 | Citations | R1 group E closed or listed as unverified in the docs | Independent reviewer |

A "no" blocks release or narrows the release notes to what passed. A threshold
changes only by a dated amendment committed before the hold-out corpora are
opened.

## Evidence required

Tagged protocol; corpus manifest with hashes; raw backtest results with SHA-256
checksums; red-team report; replication record; pilot sign-off; differential-test
logs including R fixtures; `*_certificates.json`; `mutation_survivors.json`;
preflight output; the release review record; R1 D1, D2 and D4 artifacts.

## Risks

| Risk | Mitigation |
|---|---|
| Too few real labelled defects | Count and licence-check first (5.2); narrow the claim to families covered |
| Too few datasets with a time axis | Report "unsupported"; do not relax the inclusion rule after results |
| Backtest confounded by dataset difficulty | Strata and adjusted effect |
| Independent parties unavailable | Release stays open; the author does not substitute |
| First run of `release.yml` fails on a step never exercised (OIDC publishing, `pypi` environment approval) | Rehearse the workflow up to the publish step on a throwaway tag in a fork; a TestPyPI dry run is not configured |
| Reusing `0.1.0b1` confuses readers of the changelog | Decide in 5.10 and say so in the changelog |
| A simulated-only gate hides a real-data failure | Real-data gates are published with their misses; types without a referent stay `unverified` |

## Out of scope

New detectors, new modalities, hosted services, and any claim beyond the
corpora tested. SOTA accuracy results (5.6) make no claim about the
qualification instrument.
